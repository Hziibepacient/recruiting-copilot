# 运行与恢复手册

## 0.3.1 更新与无发送验收

公开源码不再包含生产账号和职位。本机 `extension/outreach-scope.json` 格式：

```json
{"account":"你的平台账号显示名","jobId":"实际职位数字ID","greeting":"平台默认招呼全文"}
```

只在本机填写；此文件和 bridge-config.json 都被 Git、构建和更新工具排除，已有配置不会随公开包替换。Python CLI 在运行时加载，扩展页面在启动时加载；修改后重启本机服务并重新打开面板。账号、岗位和问候必须与原平台一致。

发送前测试使用 `python bridge.py serve --read-only`，或 `tools/start-bridge.ps1 -ReadOnly`。此模式在派发前拒绝所有 run，不消费许可；仍允许读取、准备和 preflight。不要同时启动另一个桥接服务。测试结束后要真正恢复业务，须先停止只读服务，再以正常模式启动并重新核验；本轮未恢复真实发送。

准备成功后提交 `{"type":"preflight","tabId":实际标签ID,"id":"本次候选人ID"}`：核对当前准备时间、审核证据、去重、额度及最终窗口里的候选人原生标识、岗位与全文问候。返回 dryRun=true、submitted=false 只证明发送前检查，不代表已发送。此命令不会消费许可，不调用最终发送。

0.3.1 页面协议为 6，必须重新加载扩展及当前猎聘页；磁盘更新不能证明旧浏览器运行时已更新。下文协议 5 和 0.3.0 迁移记录属于旧版本背景。

新台账写入 `.runtime/ledger`，证据写入 `.runtime/evidence`、`.runtime/attempts`。旧台账先用 `python tools/import-legacy-ledger.py --source "旧台账目录"` 复制：校验数据、拒绝覆盖不同文件、核验哈希、保留源文件。当前电脑已复制 9 个日文件；不能用空台账冒充历史已导入。旧工具若仍在运行会继续写旧位置，升级前须停用旧执行器并再次核对冲突，不能双套运行。

`node tools/synthetic-flow.mjs` 生成生产 content.js 在合成 DOM 上的逐步骤日志，默认写入 `.runtime/test-results/synthetic-flow.json`。它没有连接平台，不能替代浏览器截图。`python tools/privacy-check.py` 检查 Git 跟踪文件，`--archive 文件.zip` 检查发布包；模式扫描不能替代人工检查候选人文字。

## 两种用途

项目展示只打开 `demo/index.html`。它与真实招聘数据无关，不需要登录、不需要本机服务。

真实业务使用工作区私有源码与原有安装目录。公开 ZIP 已替换账号和职位，不能当生产配置覆盖已安装版本。

## 启动

在项目目录运行：

```powershell
python bridge.py status
python bridge.py serve
```

首次 status 会创建本机配置。服务只监听 127.0.0.1:18763。首次配置不得上传或放进公开仓库。保持扩展面板打开；用户登录状态由浏览器自己管理。

需要隐藏启动可以使用 `tools/start-bridge.ps1`。它不会设置开机自动运行，不会启动招聘发送。已有端口会提示，不擅自结束其他进程。

## 更新已有安装

先停止发送并核对无未完成任务。使用 `tools/update-extension.ps1 -InstalledPath "实际 extension 目录"` 更新源码，保留 bridge-config.json，备份被替换文件并校验 SHA-256。不要删除或重新安装扩展，否则可能改变扩展 ID 和本地存储。

随后在管理扩展中刷新 TTC 猎聘助手，重新打开控制页，再刷新猎聘标签页加载协议 5。更新磁盘文件不等于浏览器已加载。首次读取详情或导入审核时迁移旧快照，事务失败保留旧数据。关闭旧控制页，避免旧版本同时写快照。

本轮可以自动复制已明确的安装目录；若浏览器未加载新代码，必须明确报告为“磁盘已更新，运行时未验收”。

## 常见状态

| 状态 | 下一步 | 不该做的事 |
|---|---|---|
| 配置缺失 | 在项目目录运行 status 生成配置，核对安装目录 | 把令牌发到聊天或公开仓库 |
| 本机服务未响应 | 查看服务状态与端口，再启动本项目服务 | 无限刷新猎聘 |
| 唯一控制权被占用 | 使用已经打开的控制页，关闭多余旧面板 | 同时运行多套发送器 |
| 页面协议不符 | 刷新当前猎聘页，再读取 health | 忽略版本差异继续点 |
| 已知相似候选人提示 | 工具正常关闭并等待消失 | 点击“免费开聊”顺带发送 |
| 未识别窗口或用户在编辑 | 保留窗口，由用户决定 | 强行删除遮罩 |
| 安全验证/额度限制 | 停止，让用户正常处理 | 自动绕过或连续重试 |
| 发送前已联系 | 跳过，不计本轮新增 | 把既有联系算成果 |
| 未知发送回执 | 优先核验原人原尝试 | 重发同一条 |
| 历史无绑定回执 | 保留待核验，人工查原会话证据 | 仅凭布尔 verified 自动归因 |
| 已停止 | 助手核验账号、额度、未决后执行 resume，再重新 prepare | 清空台账“恢复” |

## 诊断与命令

`python bridge.py status` 返回最近心跳及未完成租约。连接正常只证明控制页能轮询，不证明猎聘页可读，也不证明发送已成功。

创建一个仅本地 JSON 命令文件，例如 `{"type":"diagnostics","tabId":实际标签页ID}`，再运行 `python bridge.py call --file 文件路径`。reloadSearch 只在停止且无未决时刷新指定搜索页并清除旧准备状态，不自动恢复发送。migrateStorage 仅触发旧快照事务迁移。state 不返回简历全文；diagnostics 显示版本、存储体积、阶段和页面健康。read 才读取当前页。命令文件保存在私有目录。

一条真实业务链路：read → 外部审核 → import → prepare → operator arm → bridge run → operator finish。不能跳过审核、许可和回执。每日预算 60、本批 20、每词成功 10 的规则独立计算；提前换词重新计本词，跨批保留余数。

`outreach_operator.py recover-arm --permit-id ID` 仅恢复准备阶段中断且证明从未派发的许可；已经 armed、consumed 或已租出的许可不能借此解除未知发送。

桥接租约永久无结果时，status 会列出。当前不自动释放不确定租约；排查客户端 inflight、服务端 lease/result 和原页面回执后处理。宁可明确停机，不假装已经恢复。

## 数据与回滚

Chrome storage.local 保存控制状态、事件与已消费许可；IndexedDB 保存每个候选人的最新快照。原始本地阅读材料和 JSONL 台账保留在私有输出目录。不要将 `.runtime`、history-verified.json、bridge-config.json 或实际候选人材料放进公开项目。

回滚前先停止并备份；0.3.0 的快照存储与旧版不同，不能仅覆盖旧JS就认为数据兼容。源码备份用于追踪，不承诺一键降级恢复旧存储。升级前保留本地证据；迁移完成后不卸载扩展。
